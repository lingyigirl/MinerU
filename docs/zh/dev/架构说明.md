# 架构说明 (Architecture)

> 本文档描述 MinerU 3.2.0 的完整工作链路、模块职责、部署方式和启动方式。

---

## 一、完整工作链路

## 二、模块职责详解

### 2.1 CLI 客户端 (`client.py`)

职责：
1. 收集输入文档（支持目录、通配符、单文件）
2. 按 processing_window_size 规划任务批次
3. 若未指定 `--api-url`，自动启动本地临时 `mineru-api` 子进程
4. 并发提交任务，实时显示进度
5. 下载结果 ZIP，解压，生成可视化 PDF

### 2.2 FastAPI 服务 (`fast_api.py`)

```
lifespan 启动:
  ├── 创建 AsyncTaskManager（后台任务调度器）
  ├── （可选）预加载 VLM 模型到显存
  └── 设置信号量并发限制

lifespan 关闭:
  ├── 等待所有运行中任务完成
  ├── 清理过期任务文件
  ├── 卸载 VLM 模型
  └── 关闭 PDF 渲染进程池

请求处理:
  POST /file_parse
    ├── 保存上传文件到临时目录
    ├── 获取信号量许可
    ├── 调用 do_parse() 或 aio_do_parse()
    ├── 清理临时文件
    ├── 打包结果（JSON 或 ZIP）
    └── 释放信号量

  POST /tasks
    ├── 保存上传文件
    ├── 创建 AsyncParseTask
    ├── 提交到 AsyncTaskManager 队列
    └── 立即返回 task_id

AsyncTaskManager:
  ├── 后台 asyncio 任务循环
  ├── 从优先队列获取下一个待处理任务
  ├── 等待信号量许可
  ├── 执行解析
  ├── 更新任务状态
  └── 定时清理过期任务
```

### 2.3 Router 网关 (`router.py`)

```
WorkerPool:
  ├── Remote upstreams: 通过 /health 定期健康检查
  └── Local workers: 管理 mineru-api 子进程

Worker 选择算法:
  1. 过滤掉不健康的 worker
  2. 按负载评分升序排序: score = queue_depth * 10 + active_tasks + pending
  3. 选择评分最低的健康 worker

请求代理:
  POST /file_parse
    ├── 暂存 multipart payload 到磁盘
    ├── 选择 worker
    ├── 转发到上游
    ├── 轮询状态直到完成
    ├── 流式转发结果（避免 OOM）
    └── 清理暂存 payload

  自动重启:
    ├── 连续 WORKER_HEALTH_FAILURE_RESTART_THRESHOLD (5) 次健康失败
    └── 自动重启本地 worker 子进程
```

### 2.4 Pipeline 后端详细链路

```
BatchAnalyze.__call__() 单轮迭代:

1. Layout detection (PP-DocLayoutV2)
   ├── RT-DETR 检测 25 类文档元素
   ├── ReadingOrder 预测阅读顺序
   └── 输出: list[bbox + label]

2. 表格内联对象提取
   ├── 从表格 bbox 中裁剪
   ├── 用于后续 MFR
   └── _extract_table_inline_objects()

3. 表格方向分类 + 有线/无线分类
   └── 输出: 修正后的表格方向 + WiredTable/WirelessTable

4. 表格 OCR
   ├── 每个表格 -> OCR det + rec
   ├── 有线表格 -> UNet 检测线 → TableRecover 重建行列 → HTML
   ├── 无线表格 -> SLANet-Plus 结构识别 → TableMatch OCR-单元格匹配 → HTML
   └── 有线/无线结果自动优选

5. 公式识别 (MFR)
   ├── UniMERNet + PP-FormulaNet-Plus（双引擎）
   ├── 按公式面积动态 batch 分组
   └── 输出: list[bbox + latex]

6. OCR 文本检测 + 识别
   ├── (可选) 去掉公式区域的检测框避免重复
   ├── 批处理: 按分辨率分组
   ├── 文本识别: 按语言分组
   └── 输出: list[text + bbox + confidence]

7. 印章检测
   └── 输出: 印章文本
```

### 2.5 VLM 后端详细链路

```
doc_analyze():

1. 分窗加载 PDF 页面图片
2. 通过 MinerUClient (OpenAI 兼容 API) 调用 VLM
3. batch_two_step_extract():
   - Step 1: Layout detection → 返回 page_blocks
   - Step 2: Content extraction → 补充表格 HTML/公式 LaTeX/阅读顺序
4. 输出: list[page_blocks]  ← 每页结构化 block 列表

ModelSingleton 管理:
  - 根据推理引擎 (vllm/lmdeploy/transformers/mlx/http-client) 创建 MinerUClient
  - 单例缓存，进程内复用
  - atexit 注册 shutdown 清理
```

### 2.6 Hybrid 后端协作模式

```
doc_analyze():

_for_each_window:
  1. VLM 做布局检测 → blocks (带 type 和 bbox)
  2. Pipeline 小模型:
     ├── Layout 小模型辅助标题拆分 (_apply_layout_title_split)
     ├── 公式识别 (build_inline_formula_inputs)
     ├── OCR 检测 (ocr_det, 批处理)
     └── OCR 识别 (按语言分组)
  3. 合并结果:
     ├── _merge_page_sidecar_items() 将 OCR det + 公式结果注入每页 model_list
     └── 通过 Hybrid MagicModel 生成统一的 preproc_blocks
```

## 三、部署方式

### 3.1 单机命令行

```bash
mineru -p /path/to/doc.pdf -o ./output
```
自动启动本地 API 子进程，解析完成后结果在 `./output/doc.pdf/vlm/`。

### 3.2 单机 API 服务

```bash
mineru-api --host 0.0.0.0 --port 8000
```
然后客户端：
```bash
mineru -p /path/to/doc.pdf -o ./output --api-url http://localhost:8000
```

### 3.3 多 GPU 部署（Router）

```bash
# 启动 Router（自动管理本地 GPU worker）
mineru-router --host 0.0.0.0 --port 8002 \
  --local-gpus 0,1 \
  --worker-host 127.0.0.1

# 或者连接已有 API 实例
mineru-router --host 0.0.0.0 --port 8002 \
  --upstream-url http://gpu0:8000 \
  --upstream-url http://gpu1:8000
```

### 3.4 Docker 部署

```bash
# 构建
docker build -t mineru:custom .

# 启动（模型运行时挂载）
docker run -d --gpus all -p 8000:8000 \
  -v /path/to/PDF-Extract-Kit-1.0:/models/pipeline:ro \
  -v /path/to/MinerU2.5-Pro-2605-1.2B:/models/vlm:ro \
  mineru:custom

# docker compose (docker/compose.yaml 可拆分三个服务)
docker compose -f docker/compose.yaml --profile api up -d
docker compose -f docker/compose.yaml --profile gradio up -d
docker compose -f docker/compose.yaml --profile openai-server up -d
```

### 3.5 国产硬件部署

`docker/china/` 目录下有适配以下硬件的 Dockerfile：
- 昇腾 NPU (`npu.Dockerfile`)
- 海光 DCU (`dcu.Dockerfile`)
- 摩尔线程 MUSA (`musa.Dockerfile`)

- 燧原 (`gcu.Dockerfile`)
- 沐曦 (`maca.Dockerfile`)
- 登临 (`ppu.Dockerfile`)

## 五、线程安全与并发策略

### PDFium 保护
`pdfium_guard.py` 维护全局 `threading.RLock`，所有 pypdfium2 API 调用需获取锁（PDFium 非原生线程安全）。

### 模型单例
各后端的 `ModelSingleton` / `AtomModelSingleton` 使用类级别字典缓存已加载模型，线程安全的多实例共享。

### API 并发控制
`fast_api.py` 使用 `asyncio.Semaphore` 限制最大并发请求数（默认 3, 可环境变量覆盖）。macOS 环境下强制为 1（MLX 引擎限制）。

### PDF 渲染进程池
`pdf_image_tools.py` 使用 `ProcessPoolExecutor` 并行渲染 PDF 页面。Linux 上从 fork 切换到 spawn 模式避免安全风险。损坏进程池自动恢复。
