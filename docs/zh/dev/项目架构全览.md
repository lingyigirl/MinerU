> **用途**: 供 AI 辅助开发时快速理解项目架构，避免每次重新扫描。
> **最后更新**: 2026-08-13
> **适用版本**: MinerU 3.4.4

---

## 一句话概述

MinerU 是一款将 PDF / 图片 / DOCX / PPTX / XLSX 解析为 Markdown 和 JSON 的文档解析工具，支持纯 CPU 和多 GPU 部署，通过 FastAPI 提供 REST API 服务。

---

## 核心数据流

```
输入文件 (PDF/图片/DOCX/PPTX/XLSX)
    │
    ├─ Office (DOCX/PPTX/XLSX) ──→ office_analyze ──→ middle_json（_backend 归一化为 "vlm"）
    │
    └─ PDF/图片 ──→ [S0/S1 智能路由，见下节] ──→ 选择后端
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
       pipeline       vlm         hybrid
      (本地小模型)  (VLM 端到端)  (VLM + pipeline)
          │            │            │
     batch_analyze  vlm_analyze  hybrid_analyze
     (layout→MFR     (VLM 推理)   (VLM 布局 + OCR/公式精炼)
      →OCR→Table)       │            │
          │            └─────┬──────┘
          │                  ▼
          │     原始模型输出 model_output
          │                  │
          │                  └──→ 写 {name}_model.json（可选）
          │                         │
          └──────────┬──────────────┘
                     ▼
     model_output_to_middle_json 归一化
                     │
                     ▼
               middle_json
                     │
                     └──→ 写 {name}_middle.json（可选）
                                │
                                ▼
              middle_json_mkcontent（union_make）
                                │
              ┌─────────────────┼──────────────────┐
              ▼                 ▼                  ▼
            *.md    *_content_list.json   *_content_list_v2.json
```

## 后端命名与 S0/S1 智能路由

`-b` / `--backend` 的 5 个可选值（默认 `hybrid-auto-engine`）：

| `-b` 取值 | 类型 | 说明 |
| --- | --- | --- |
| `pipeline` | 本地小模型 | layout + MFR + OCR + Table，纯 CPU 可用 |
| `vlm-auto-engine` | 本地 VLM | 自动选推理引擎（vLLM / LMDeploy / MLX） |
| `vlm-http-client` | 远程 VLM | 连接远程 `mineru-api`（`server_url`），无需本地 torch |
| `hybrid-auto-engine` | 本地 hybrid | VLM 布局 + pipeline 精炼，**默认** |
| `hybrid-http-client` | 远程 hybrid | 连接远程 `mineru-api`，本地仅需少量算力 |

命名解析：分发时先按 `vlm-` / `hybrid-` 前缀确定后端，剥离前缀后
`auto-engine` 交给 `get_vlm_engine()` 自动选择具体推理引擎，最终拼成
`vllm-engine` / `vllm-async-engine` / `lmdeploy-engine` / `mlx-engine` / `transformers`。

S0/S1 智能路由链路（`doc_type=auto` 时启用，见 `_try_smart_routing`）：

```
PDF 字节流
  → [S0] 文档质量分析（doc_quality.py）：DPI / 模糊 / 印章 / 旋转
  → [S1] 文档分类（doc_classifier.py）："信号灯"三路路由
      ├─ 🟢 DOCUMENT_PARSE：通用文档 → 按 OCR 难度选 vlm/hybrid/pipeline
      ├─ 🟡 STRUCTURED_TABLE：密集表格 → Hybrid + OCR 补充
      └─ 🔴 FORM_KVP：票据/卡证 → KVP Pipeline（本地 OCR / VLM 纠错）
  → select_engine_route() 返回 EngineRoute（含 fallback 链）
```

`doc_type` 参数取值：

| 取值 | 说明 |
| --- | --- |
| `general` | 跳过 S0/S1，按 `-b` 指定的 backend 直接解析 |
| `form_kvp` | 强制走 KVP Pipeline（票据/卡证 KVP 提取） |
| `auto`（默认） | 运行 S0 → S1 自动分类后选择引擎 |

## 三层架构

### 第 1 层：接口层 (`mineru/cli/`)

对外暴露的入口，不包含解析逻辑。

| 组件                   | 角色                           |
| ---------------------- | ------------------------------ |
| `client.py`          | CLI 命令`mineru`，编排客户端 |
| `fast_api.py`        | FastAPI 服务，REST API         |
| `router.py`          | 多 GPU 负载均衡网关            |
| `gradio_app.py`      | Web UI (Gradio)                |
| `vlm_server.py`      | VLM 推理服务器入口（`mineru-vllm-server` / `mineru-lmdeploy-server` / `mineru-openai-server`） |
| `models_download.py` | 模型下载 CLI                   |

### 第 2 层：业务逻辑层 (`mineru/backend/`)

所有解析后端的实现，是项目核心。

```
backend/
├── pipeline/     ← 小模型管线（layout + MFR + OCR + Table）
├── vlm/          ← VLM 大模型端到端
├── hybrid/       ← VLM + Pipeline 混合模式
├── office/       ← DOCX/PPTX/XLSX 原生解析
└── utils/        ← 跨后端共享工具
```

每个后端遵循统一模式：

1. **analyze** — 解析输入，产出 page_blocks / model_list
2. **MagicModel** — 结构化（classify caption, group visual blocks...）
3. **model_output_to_middle_json** — 归一化为 middle_json
4. **middle_json_mkcontent** — 渲染为 Markdown / JSON

### 第 3 层：模型与数据层 (`mineru/model/` + `mineru/data/`)

#### 模型层 (`mineru/model/`)

| 子包         | 功能         | 核心模型                                |
| ------------ | ------------ | --------------------------------------- |
| `layout/`  | 版面检测     | PP-DocLayoutV2 (RT-DETR + ReadingOrder) |
| `mfr/`     | 公式识别     | UniMERNet + PP-FormulaNet-Plus          |
| `ocr/`     | 文字识别     | PaddleOCR-Torch                         |
| `table/`   | 表格识别     | SLANet-Plus (无线) + UNet (有线)        |
| `vlm/`     | VLM 推理     | vLLM / LMDeploy / MLX 服务器            |
| `docx/`    | DOCX 转换    | DocxConverter                           |
| `pptx/`    | PPTX 转换    | PptxConverter                           |
| `xlsx/`    | XLSX 转换    | XlsxConverter                           |
| `ori_cls/` | 方向分类     | PP-LCNet                                |
| `utils/`   | 共享基础设施 | BaseOCRV20, TextSystem                  |

#### 数据层 (`mineru/data/`)

```
data/
├── data_reader_writer/   ← 读写抽象 (FileBased, S3, Dummy)
└── io/                   ← 底层 IO (HTTP, S3)
```

## 后端的区别

> 注：`office` 仅用于 DOCX/PPTX/XLSX 原生解析，不参与 PDF 的 S0/S1 路由；`vlm` / `hybrid`
> 实际以 `-auto-engine`（本地）和 `-http-client`（远程）两种形态存在，见「后端命名与 S0/S1 智能路由」。

| 维度     | pipeline         | vlm               | hybrid            | office         |
| -------- | ---------------- | ----------------- | ----------------- | -------------- |
| 模型类型 | 小模型 (ONNX/PT) | VLM (Qwen2-VL)    | VLM + 小模型      | 无 (纯解析)    |
| 精度     | ~86              | ~90+              | ~90+              | 原生（无损）   |
| 最低显存 | 4 GB             | 8 GB              | 8 GB              | 无要求         |
| 纯 CPU   | ✅               | ❌                | ❌                | ✅             |
| 适用格式 | PDF/图片         | PDF/图片          | PDF/图片          | DOCX/PPTX/XLSX |
| 推理引擎 | 无               | vLLM/LMDeploy/MLX | vLLM/LMDeploy/MLX | 无             |
| 速度     | 中等             | 较慢              | 较慢              | 极快           |

## 核心中间格式：middle_json

所有后端最终都产出统一的 `middle_json` 结构：

```
middle_json = {
    "_backend": "pipeline" | "vlm" | "hybrid",
    "pdf_info": [                          ← 页面级信息
        {
            "page_idx": int,
            "width": float, "height": float,
            "preproc_blocks": [...],       ← 原始检测块
            "para_blocks": [...],          ← 结构化段落块
            "images": [...],               ← 图片裁剪信息
        }
    ],
    "_parse_settings": {...}               ← 解析参数记录
}
```

> 注：`_backend` 实际只有 `pipeline` / `vlm` / `hybrid` 三种取值；Office 后端解析后会经
> `_normalize_to_vlm_format` 把 `_backend` 归一化为 `"vlm"`。

## 输出格式

| Mode                | 格式     | 说明                              |
| ------------------- | -------- | --------------------------------- |
| `MM_MD`           | Markdown | 多模态，图片用相对路径            |
| `NLP_MD`          | Markdown | NLP 友好，额外文本排版            |
| `CONTENT_LIST`    | JSON     | 块级结构化列表 v1                 |
| `CONTENT_LIST_V2` | JSON     | 块级结构化列表 v2（含 span 细节） |

## 服务编排模式

```
mineru CLI client
    │
    ├─ --api-url 未指定 ──→ 自动启动本地临时 mineru-api 子进程
    │                           │
    └─ --api-url 指定 ────→ 连接远程 mineru-api 或 mineru-router
```

```
mineru-router
    │
    ├─ 管理远程上游 ──→ mineru-api (remote host)
    └─ 管理本地 worker ──→ mineru-api 子进程 (local GPU)
        自动健康检查 + 故障重启 + 负载均衡
```

## 技术栈概要

- **Web 框架**: FastAPI + uvicorn
- **CLI 框架**: Click
- **ML 框架**: PyTorch, ONNX Runtime, Transformers
- **推理引擎**: vLLM, LMDeploy, MLX
- **PDF 处理**: pypdfium2, pypdf, pdfminer.six, pdftext
- **图片处理**: Pillow, OpenCV
- **Office 文档**: python-docx, python-pptx, openpyxl, mammoth, lxml
- **日志**: loguru
- **异步**: asyncio + httpx
- **模型源**: HuggingFace Hub, ModelScope
