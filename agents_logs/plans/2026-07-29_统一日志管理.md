# 统一日志管理方案

## 上下文

当前项目 69 个文件各自 `from loguru import logger`，3 个入口点各自独立配置 `logger.remove()/logger.add()`，全部都只输出到 stderr，没有任何文件日志。`mineru/utils/log_utils.py` 是从 RAGFlow 复制来的死代码（从未被调用），且存在外部依赖导入错误。

**目标**：适配 `log_utils.py` 到项目，统一配置入口，添加文件日志输出，同时最小化对上游代码的改动以降低合并冲突。

## 方案

### 1. 重写 `mineru/utils/log_utils.py`

保持文件路径不变。修改内容：

**移除**：
- `from common.file_utils import get_project_base_directory`（项目无此依赖，`import` 即报错）

**新增**：
- `MINERU_LOG_DIR` 环境变量支持（默认 `~/mineru`），日志输出路径为 `{MINERU_LOG_DIR}/logs/{name}.log`
- `console_sink` 参数，允许 CLI 入口传入自定义 `LiveAwareStderrSink`
- 默认控制台输出改为 `sys.stderr`（匹配现有三个入口点的行为）

**改名适配**：
- 内部读取 `MINERU_LOG_LEVEL` 环境变量（替代 RAGFlow 的 `LOG_LEVEL`）
- `LOG_LEVELS` → `MINERU_LOG_LEVELS`
- docstring 中去掉 `ragflow_server` 引用

**保留**：
- `InterceptHandler` — 标准库 logging 桥接
- `init_root_logger()` — 统一初始化
- `log_exception()` — 异常诊断记录
- `log_time()` — 函数耗时装饰器
- `DEFAULT_LOG_FORMAT` — 日志格式

**函数签名**：
```python
def init_root_logger(
    logfile_basename: str,
    log_format: str | None = None,
    log_dir: str | None = None,
    console_sink: Any = None,
) -> None:
```

- `log_level` 不暴露为参数，统一从 `MINERU_LOG_LEVEL` 环境变量读取（默认 `INFO`）
- 首次调用设置 `initialized_root_logger = True`，后续调用为 no-op（防止重复初始化）

### 2. 改造 `mineru/cli/fast_api.py`（3 行 → 2 行）

**当前（73-75 行）**：
```python
log_level = os.getenv("MINERU_LOG_LEVEL", "INFO").upper()
logger.remove()
logger.add(sys.stderr, level=log_level)
```

**改为**：
```python
from mineru.utils.log_utils import init_root_logger
init_root_logger("mineru_api")
```

日志文件输出到：`~/mineru/logs/mineru_api.log`

### 3. 改造 `mineru/cli/gradio_app.py`（3 行 → 2 行）

**当前（29-31 行）**：
```python
log_level = os.getenv("MINERU_LOG_LEVEL", "INFO").upper()
logger.remove()  # 移除默认handler
logger.add(sys.stderr, level=log_level)  # 添加新handler
```

**改为**：
```python
from mineru.utils.log_utils import init_root_logger
init_root_logger("mineru_gradio")
```

日志文件输出到：`~/mineru/logs/mineru_gradio.log`

### 4. 改造 `mineru/cli/client.py`（3 行 → 3 行，行为增强）

**当前（48 行 + 257-259 行）**：
```python
log_level = os.getenv("MINERU_LOG_LEVEL", "INFO").upper()
...
_stderr_sink = LiveAwareStderrSink(sys.stderr)
logger.remove()
logger.add(_stderr_sink, level=log_level)
```

**改为**：
- 删除第 48 行的 `log_level = os.getenv("MINERU_LOG_LEVEL", "INFO").upper()`
- 将 257-259 行改为：
```python
_stderr_sink = LiveAwareStderrSink(sys.stderr)
from mineru.utils.log_utils import init_root_logger
init_root_logger("mineru_cli", console_sink=_stderr_sink)
```

日志文件输出到：`~/mineru/logs/mineru_cli.log`

### 5. 不改动的部分

- **所有 69 个模块的 `from loguru import logger` 保持不变** — 这是 loguru 的设计模式，无需改动
- **`LiveAwareStderrSink` 类定义保持不变** — 继续在 `client.py` 中，继续对接 `LiveTaskStatusRenderer` 进度条

## 环境变量一览

| 变量 | 默认值 | 说明 |
|---|---|---|
| `MINERU_LOG_LEVEL` | `INFO` | 根日志级别 |
| `MINERU_LOG_DIR` | `~/mineru` | 日志文件存放目录 |
| `MINERU_LOG_LEVELS` | 内置噪声包 → WARNING | 分模块日志级别（如 `peewee=DEBUG,urllib3=WARNING`） |

## 合并风险评估

- `mineru/utils/log_utils.py`：新文件（当前 `??` 未跟踪），上游无同名文件 → **零冲突**
- `mineru/cli/fast_api.py`：3 行替换，上游无 `[自定义]` 标记 → **低冲突**（1-2 行差异）
- `mineru/cli/gradio_app.py`：3 行替换 → **低冲突**
- `mineru/cli/client.py`：删除 1 行 + 替换 3 行 → **低冲突**

总计改动约 15 行，远小于 `[自定义]` hook 点的合并工作量。
