# KVP 本地引擎：配准精度修复

## Context

`feature/kvp-local-kie` 分支的 `pp-structure` 本地 KVP 引擎存在 3 类配对错误，导致定期存单解析结果差距较大：

1. **最长匹配缺陷**：`_try_split_concatenated` 对 `"存人金额（大写）"` 先用 `"存入金额(大写)"` 完整匹配得到空 value，跳过；再用 `"存入金额(小写)"` 部分匹配 `"存人金额"` 返回 `value="（大写）"` — 输出 `存入金额(小写): （大写）`。
2. **OCR 网格合并**：同一行的 `开户日+起息日` → `"2024053120240531"`，`存期+到期日+年利率+预估到期本息+是否凭密码` → `"二年202005312.550000%261,127.0是"`。没有拆分逻辑，导致值对不上标签。
3. **词典不完整**：缺"账号"字段；部分 OCR 误读没有对应的容错模式（如"签发日"→"签发日期"、"到期□"→"到期日"、"存人时经办"→"存入时经办"）。

## 修改文件清单

| 文件 | 改动 |
|------|------|
| `mineru/utils/custom/kvp_local_engine.py` | 修复 1：`_try_split_concatenated` 最长匹配；修复 2：新增 `_split_grid_merged_values` 网格拆分 |
| `mineru/utils/custom/labels/deposit_slip.py` | 修复 3：补全词典 + OCR 容错模式 |

## 详细设计

### 修复 1：`_try_split_concatenated` 最长匹配

**现状问题**：
```python
for pattern, label in compiled_labels:      # 按注册顺序遍历
    m = pattern.match(text)
    if m:
        value = text[m.end():].strip()
        if value:                           # 第一个有非空 value 的就返回
            return label, value
```

**修复**：收集所有匹配 → 按匹配长度降序排列 → 取最长匹配。若最长匹配的 value 为空或 value 以全角/半角括号开头（说明是标签修饰如"（大写）"而非真实值），则不拆分，返回 `(None, None)` 让该 box 被当作纯标签处理。

```python
def _try_split_concatenated(text, compiled_labels):
    matches = []
    for pattern, label in compiled_labels:
        m = pattern.match(text)
        if m:
            matches.append((m.end(), label))
    if not matches:
        return None, None
    matches.sort(key=lambda x: -x[0])  # 最长匹配优先
    
    for match_end, label in matches:
        value = text[match_end:].strip()
        if not value:
            return None, None          # 完整匹配 → 纯标签，不拆分
        if value and value[0] in '（(':
            continue                   # 后缀是括号修饰，尝试下一个（更短）匹配
        return label, value
    return None, None
```

### 修复 2：网格布局值拆分 `_split_grid_merged_values`

在 `_pair_kvp` 的 C 阶段（空间配对）之后，新增 D 阶段。

**D 阶段流程**：

**D1. 识别孤儿标签**：配对后仍无 value 的标签 boxes（已在 `labels` 列表中但未配对的）。

**D2. 标签行聚类**：将孤儿标签按 y 中心聚类（容差 30px），每组为一行。行内按 x 排序。

**D3. 找宽值框**：对每个未使用的 value box，检查其 x 区间是否跨越行中多个标签列。判断标准：value box 的 x 范围覆盖 ≥2 个标签的 x 中心。

**D4. 比例拆分**：对宽值框，按各标签列的 x 宽度比例拆分字符串：
```
merged_text = "二年202005312.550000%261,127.0是"
columns = [(存期, x1=948, x2=1087), (到期日, x1=1087, x2=1296), (到期利息, x1=1296, x2=1735), ...]

总宽度 = 1961 - 948 = 1013
存期占比 = (1087-948)/1013 = 0.137 → 取 2 个字符 → "二年"
到期日占比 = (1296-1087)/1013 = 0.206 → 取 8 个字符 → "20200531"
...
```

**D5. 格式提示优化**（可选增强）：在标签词典中新增可选的第三元组 `value_hint`（值格式正则），拆分前尝试用格式正则匹配子串定位精确切分点。

### 修复 3：补全 `deposit_slip.py` 词典

新增/修正标签：

| 标签 | 正则 | 说明 |
|------|------|------|
| 账号 | `r"账[号號户]"` | 新增（原词典缺失） |
| 签发日期 | `r"签[发發][日□口](?:期)?"` | OCR 容错："签发日" |
| 到期日 | `r"到[期期][日□口]?"` | OCR 容错："到期□" |
| 起息日 | `r"起[息息][日□口]?"` | OCR 容错 |
| 存入金额(大写) | `r"存[入款人]金[额額](?:[(（].*[)）])?"` | 已有，正确 |
| 存入时经办 | `r"(?:存[入款人]时)?经[办辦]"` | OCR 容错："存人时经办" |
| 复核(授权) | `r"复[核械](?:[(（].*授[权權].*[)）])?"` | OCR 容错："复械" |
| 预估到期本息 | `r"预[估估]?到[期期]本[息息]"` | OCR 容错 |
| 年利率 | `r"(?:年)?利[率率]"` | 已有 |
| 到期利息 | `r"到[期期]利?[息息]"` | OCR 容错："到期息" |
| 操作员代码 | `r"操[作做][员貝](?:[代碼码编]?[码碼]?)?"` | 已有 |
