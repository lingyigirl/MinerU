# Plan: 通过远程 VLM 服务解决 Docker 容器 GPU 显存不足

## Context

Docker 容器（端口 8011）使用 `hybrid-auto-engine` 后端，需要本地加载 VLM 模型。但 GPU 2 已被旧版 `mineru-api`（端口 8010）的 VLM 占用 21.9 GiB，剩余 9.1 GiB 不足以让 vLLM 按 `gpu_memory_utilization=0.2`（需 9.47 GiB）启动，导致 `Engine core initialization failed`。

旧版 VLM 的 `VLLM::EngineCore`（PID 1239439）是 multiprocessing 子进程，IPC 通道私有，**无法被 Docker 容器直接复用**。

**替代方案**：让 Docker 容器的 hybrid 后端通过 HTTP 调用端口 8010 上已加载的 VLM，本地仅保留 pipeline（OCR/公式/表格）处理。

## 核心发现

Hybrid 后端的 VLM 和 Pipeline 是**独立加载**的：

- `HybridModelSingleton().get_model()` → 加载 pipeline 模型（layout/OCR/MFR/table）
- `ModelSingleton().get_model(backend, model_path, server_url)` → 加载 VLM 模型

当 `backend="http-client"` 时，VLM 不加载本地模型，而是通过 HTTP 调用远程服务。Pipeline 模型不受影响。

**关键代码路径**（common.py）：
```
do_parse() → backend.startswith("hybrid-") → 剥离前缀 → 解析引擎名
  → _process_hybrid(backend=..., server_url=...) 
    → if not backend.endswith("client"): server_url = None  ← 这里清除 server_url
    → hybrid_doc_analyze(backend=..., server_url=...)
      → ModelSingleton().get_model(backend, model_path, server_url)
```

## 修改方案

### 1. `mineru/cli/common.py` — 添加 VLM 远程服务支持

在 `do_parse()` 和 `aio_do_parse()` 中，hybrid 和 vlm 分发路径上，引擎解析完成后、调用 `_process_hybrid`/`_process_vlm` 之前，添加环境变量检查：

```python
# [自定义] 检查是否有远程 VLM 服务可用
# 当 MINERU_VLM_SERVER_URL 设置时，使用 http-client 后端连接远程 VLM，
# 避免在本地加载 VLM 模型（节省 GPU 显存）
_vlm_server_url = os.environ.get("MINERU_VLM_SERVER_URL")
if _vlm_server_url and not backend.endswith("client"):
    logger.info(f"[自定义] 使用远程 VLM 服务: {_vlm_server_url}")
    backend = "http-client"
    server_url = _vlm_server_url
```

**需修改的位置**（共 4 处）：

| 函数 | 大致行号 | 路径 |
|---|---|---|
| `do_parse` | ~1101（hybrid auto-engine 解析后） | hybrid 同步路径 |
| `do_parse` | ~1085（vlm 引擎解析后） | vlm 同步路径 |
| `aio_do_parse` | ~1225（hybrid auto-engine 解析后） | hybrid 异步路径 |
| `aio_do_parse` | ~1217（vlm 引擎解析后） | vlm 异步路径 |

由于 `_process_hybrid` 和 `_process_vlm` 中的 `if not backend.endswith("client"): server_url = None` 逻辑，必须将 backend 改为 `"http-client"`（以 `client` 结尾），server_url 才会被保留传递到 `ModelSingleton().get_model()`。

### 2. `compose.yaml` — 添加环境变量

```yaml
environment:
  MINERU_VLM_SERVER_URL: http://172.19.0.1:8010  # 复用端口 8010 的 VLM 服务
```

其中 `172.19.0.1` 是 Docker 网关 IP（容器 `172.19.0.3` 的网关），指向宿主机上端口 8010 的旧版 mineru-api。

### 效果

- 修改前：Docker 容器尝试本地加载 VLM → GPU 显存不足 → 409 错误
- 修改后：Docker 容器发现 `MINERU_VLM_SERVER_URL` → 切换 VLM 为 http-client → 本地仅加载 pipeline 模型 → VLM 推理通过 HTTP 发到端口 8010 → 正常完成

## 验证方法

1. 修改 `compose.yaml`，添加 `MINERU_VLM_SERVER_URL` 环境变量
2. 重启容器：`docker compose restart`
3. 发送测试请求（使用之前失败的 `电子回单700电费2021216.pdf`）：
   ```bash
   curl -X POST http://172.19.0.3:8011/file_parse \
     -F 'files=@电子回单700电费2021216.pdf' \
     -F 'backend=hybrid-auto-engine' \
     -F 'doc_type=auto' \
     -F 'return_md=true'
   ```
4. 验证：
   - 请求返回 200（而非 409）
   - 容器日志显示 `[自定义] 使用远程 VLM 服务: http://172.19.0.1:8010`
   - 容器内 GPU 显存占用不增加（不加载新的 VLM）
   - 端口 8010 的旧版 mineru-api 正常处理 VLM 请求
